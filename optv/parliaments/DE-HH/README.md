# Hamburgische Bürgerschaft (DE-HH)

This directory implements the OpenParliamentTV pipeline for the Hamburgische Bürgerschaft (WP 23). It is built on a per-speech video spine from the mediathek. Text comes from the mediathek's WebVTT subtitles until the Plenarprotokoll PDF is published, then from the PDF via an **experimental, unvalidated** PDF→TEI text path (see below). See [docs/ADDING-A-PARLIAMENT.md](../../../docs/ADDING-A-PARLIAMENT.md) for repo-wide context and the DE-SH / DE-BY / DE-BW READMEs for the same regime. Among these German Landtage it is the richest media source: genuine per-TOP agenda, a server-cut video clip per speech, **real per-speech wall-clock timestamps**, source-native per-speech UUIDs and time-aligned subtitles. For how its data shape compares to the cross-parliament model, see [Architecture/DATA-STRUCTURES.md](https://github.com/OpenParliamentTV/OpenParliamentTV-Architecture/blob/main/DATA-STRUCTURES.md).

## Data model

The media stream is the spine (the mediathek session pages, built and run by Intermediate Engineering, im-en.com). Each sitting carries text from one source:

- **Subtitles** (until the protocol is published): from 2022-06-15 each mediathek clip has a WebVTT subtitle track, generated by speech recognition and corrected for the mediathek. Fetched per speech, its cues are timed against the speech's own clip, so they become `textContents[].type = "generated"` with sentence timings and need no forced alignment. They follow the spoken words closely but carry no interjections and no speaker names.
- **Plenarprotokoll** (ParlDok PDF, 3.5 to 5.5 months after the sitting): parsed via `optv.shared.pdf2tei` and joined onto the spine in the merger (`join_text_to_spine`), so matched speeches carry verbatim `type = "proceedings"` text (unmatched keep `[]`), aligned with aeneas against the speech clip (see Known limitations).

Scripts:

- `scraper/fetch_archive.py` → the candidate session index (`metadata/archive-wp{N}.json`). Session URLs are predictable (`/sitzung/{WP}/{n}/`), so discovery is a `1..max` enumeration; the upper bound is the highest sitting linked from the mediathek's plenary list (`/sitzungen/plenar`), read on every run and merged into the cached index (`--max-session` overrides it). Operator-supplied URLs (`--session` / `metadata/seed-urls.txt`) are merged in.
- `scraper/fetch_media.py` → fetches each session page and parses its static markup (`scraper/common.py:parse_session_page`) into `original/media/{session_id}-items.json` (agenda items + per-speech records). Candidate pages that 404 (gaps in the enumeration) are skipped.
- `scraper/fetch_proceedings.py` → downloads the Plenarprotokoll PDF into `original/proceedings/{session_id}.pdf` via ParlDok's predictable resolver (`parldok/dokument/{wp}/art/Plenarprotokoll/num/{nth}`, no document-id lookup); `parsers/proceedings2json.py` (`optv.shared.pdf2tei`) parses it for the merger's text join.
- `scraper/fetch_subtitles.py` → for sittings without a protocol PDF, fetches each speech's subtitle track (per-speech clip master → subtitle playlist → segments, merged) into `original/subtitles/{session_id}/{speechPk}.vtt`. About 2,600 requests for a six-hour sitting.
- `parsers/media2json.py` → flattens to `original/media/{session_id}-media.json`: one record per speech, with the name split into chair-role prefix + `Firstname Lastname`, faction vs government role from `data-speakerFunction`, the speech's own clip URL (clean and sign language), real wall-clock `start`/`end`, and the subtitle cues re-segmented into timed sentences (`optv.shared.vtt`, German spaCy sentencizer).

The mediathek session page (`mediathek.buergerschaft-hh.de/sitzung/{WP}/{n}/`) is **static HTML** carrying the full spine. Each Tagesordnungspunkt is a `<video id="sessionitem-{UUID}">` whose `data-cleanStreamUrls` holds a **server-side-clipped HLS master** (`/hls/clipFrom/{ms}/clipTo/{ms}/{date}/clean_{UUID}/…/master.m3u8`, ms into the day's recording), plus a sign-language `data-signStreamUrls` variant with its own clip range. Each speech is a `<div class="speech">` with `data-speechPk` (UUID), `data-speechLegacyId` (numeric in WP 22, `None` in WP 23), `data-start` + `data-duration` (seconds, **relative to that TOP's clip**), `data-sessionItemId`, `data-speakerNameWithoutFunction`, `data-speakerFunction`, and a per-speech `video-download/?start={unix}&stop={unix}` link whose timestamps give the real wall-clock speech start/stop. The server cuts any range: the TOP's clip URL with `clipFrom`/`clipTo` narrowed to `clipFrom + start·1000 … clipFrom + (start + duration)·1000` is the speech's own clip, the same URL the Parlamentsdatenbank's player links use. A clip has subtitles when its urlset lists a WebVTT file (`lang/deu/{date}_clean.vtt`).

## Merge strategy

No cross-source matching for the spine: `merger/merge_session.py` is a single-source translation pass from the per-speech intermediate records into Stage 2 (the media stream is the authoritative spine). One `agendaItem` per TOP (`id = "TOP-{n}"` when numbered, else a capped title slug, classified via `optv.shared.agenda_types.classify_de_hh`), one `people[]` entry per speech, and media in per-speech video file mode: `videoFileURI` is the speech's server-cut HLS clip, `media.duration` its length, `additionalInformation.startOffset = 0` / `endOffset = duration`, and `signLanguageVideoFileURI` the sign-language clip of the same range. `sourcePage` is made unique per speech via the mediathek's own `#rede-{speechPk}` anchor (the platform keys speech identity on it). `media.originMediaID` is the source-native `speechPk` UUID; there is no joint media+proceedings id, so speeches carry no `originID`. Speech `dateStart`/`dateEnd` are **real wall-clock** (from the video-download timestamps, UTC), so `debug.timesAreVideoRelative = false`.

Text: when the protocol is parsed, it is joined onto the spine (`join_text_to_spine`, `type = "proceedings"`); otherwise each speech with subtitles gets them as `type = "generated"` text with sentence timings (`debug.textSource = "subtitles"`, `debug.confidence = 1.0`, as the text is cut by the speech's own time range). The align hook in `workflow.py` follows the source: subtitle sittings are only stamped (`debug.alignDuration`, `debug.alignSource = "subtitles"`, `media.aligned`), protocol sittings are aligned with aeneas against each speech clip (`align_prep.py`).

When a protocol arrives for a sitting already published with subtitle text, `scraper/fetch_proceedings.py` queues it in `cache/de-hh-protocol-upgrades.txt`, and the `update` wrapper re-runs the queued sittings with `--rebuild` so the protocol text replaces the subtitles (the publish guard refuses a changed transcript otherwise). The Conductor calls `workflow.py` directly and does not read this queue.

## Running

```sh
# Convenience wrapper (period 23 baked in; second --rebuild pass for queued protocol upgrades)
./update /path/to/OpenParliamentTV-Data-DE-HH

# Pre-NEL, (re)generate the local entity dump (Wikidata P39 Q19360355 + WP-23 parties):
python optv/parliaments/DE-HH/scraper/build_entity_dump.py /path/to/OpenParliamentTV-Data-DE-HH

# Explicit, single test session incl. alignment and NER:
./workflow.py --period=23 /path/to/OpenParliamentTV-Data-DE-HH \
    --download-original --merge-speeches --link-entities \
    --align-sentences --extract-entities --ner-api-endpoint http://localhost:8090/service \
    --limit-session '23018' \
    --session 'https://mediathek.buergerschaft-hh.de/sitzung/23/18/'

# Validate the published output:
python -m optv.shared.validators.cli --dir /path/to/OpenParliamentTV-Data-DE-HH/processed --schema full
```

Session discovery enumerates `/sitzung/{period}/{n}/` for `n = 1..max`; the result is cached in `archive-wp{N}.json`. The plenary list only links the most recent sittings of the current term, so for an older term (WP 22) pass `--max-session N` or seed URLs.

## Access notes

The mediathek is plain public HTML — no auth, no anti-bot. Everything the spine needs is in the static page markup (no JSF ViewState like DE-BY, no result-cap AJAX like DE-SH); the clips and subtitles are plain HLS. The proceedings text comes from ParlDok (the Parlamentsdatenbank, `buergerschaft-hh.de/parldok/`), which cross-references proceedings and video. Although ParlDok presents as a web search interface, each Plenarprotokoll is also reachable by a predictable, document-id-free URL (`parldok/dokument/{wp}/art/Plenarprotokoll/num/{nth}`) that streams the PDF directly, so `scraper/fetch_proceedings.py` fetches it without scraping the search.

## Known limitations

- **Experimental, unvalidated protocol text path.** The Plenarprotokoll PDF (ParlDok) is parsed via `optv.shared.pdf2tei` and joined onto the spine, and `align`/`ner` run on the result. None of this has been validated — there is no Whisper-QC/text-fidelity audit yet, and the PDF→TEI extraction and the text↔spine join still need refinement. **Not ready for platform integration.**
- **Subtitles are not the record.** They follow the spoken words but carry no interjections and no speaker names, so everything said within a speech's time range is attributed to its speaker; their sentence timings are interpolated within each cue. Sittings before 2022-06-15 have no subtitles.
- **NEL coverage caveat** (DE-SH/DE-BY/DE-BW class): the entity dump is built from Wikidata `P39 wd:Q19360355` ("member of the Hamburg Parliament"); it misses current WP-23 members lacking that statement and government members (`Senator(in)`, `Bürgermeister(in)`) who are not sitting MdHB. On the 23018 smoke test person-NEL is 91/98 and faction-NEL 96/97. Fixable downstream by enriching the SPARQL or scraping the Bürgerschaft roster (abgeordnetenwatch parliament id 3, CC0).
- **`data-speakerFunction` is overloaded.** It is the faction for MPs (`SPD`, `GRÜNE`, `CDU`, `Die Linke`, `AfD`, `Fraktionslos`) but a government role for senators (`Senator`); the parser routes party values to `faction` and everything else to `role`. Chair roles (`Präsidentin` …) live in the name field and are split off there.
- **WP 23 only** (the current term). The mediathek covers WP 22 (2020–2025) and an archive back to 2017, but only WP 23 has been exercised.
